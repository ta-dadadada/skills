# Visual language

Product identity, content, and existing tokens supply the visual direction and
concrete values. Use the following checks within that direction.

- Give status, selection, and primary actions a consistent semantic color treatment.
- Establish hierarchy with alignment, spacing, typography, borders, and surface
  contrast. Reserve elevation for meaningful layering.
- Give containers a grouping purpose. Keep comparable rows on a shared surface;
  distinguish sections without enclosing every element in a card.
- Tune density to simultaneous information needs and input devices. Preserve
  legible text, usable targets, and focus indicators as rows become compact.
- Reuse a small typographic hierarchy; distinguish titles, labels, values, and
  metadata through consistent roles rather than many unrelated sizes.
- Use text for unfamiliar actions. For icon controls, use the naming
  requirements in [accessibility.md](accessibility.md); add tooltips where useful,
  available on focus as well as hover.
- Distinguish hover, focus, selection, pending, and inactive states. Ensure text,
  controls, and focus indicators meet the project's applicable contrast targets.
- Use shared tokens for radius, borders, spacing, and elevation. If dark mode is
  in scope, preserve surface hierarchy and semantic meaning in both themes.
- Evaluate decorative effects against the page's purpose and reading hierarchy.
  Preserve access to primary content and actions within the chosen visual style.

Check long labels, dense rows, realistic empty space, zoom, and narrow screens.
A restrained screenshot does not establish that people can read or operate it.
